    5. Hoofdstuk 4 - De Kotlin-client voor de applicatie RdvMedecins

    5.1. Overzicht van de architectuur

    Deze client communiceert met de server [rdvmedecins-nestjs-server] van de cursus - die volledig ongewijzigd blijft - via dezelfde routes: HTTP (POST [/login], GET [/getAllDoctors], GET [/getAllClients], GET [/getDoctorScheduleOfDay/:doctorId/:day], POST [/addAppointment], POST [/deleteAppointment]), met dezelfde JSON-envelop [{ status, data }] en dezelfde tokenauthenticatie [JWT] (header [Authorization: Bearer <token>]).

    Laten we deze code toelichten:

    • regel 14: [android.permission.INTERNET] - zonder dit recht mislukt elke verbinding met de server. Dit is een „normaal” recht: het wordt bij de installatie verleend zonder de gebruiker om toestemming te vragen;

// RdvMedecinsApplication.kt
// -------------------------------------------------------------------------
// Eerste helft van de lib/main.dart van de Flutter-versie: de services van de
// applicatie opbouwen, EENMALIG.
//
// Waarom een Application-klasse? Op Android wordt het scherm (de Activity, zie
// MainActivity) bij elke rotatie van de telefoon VERNIETIGD en daarna OPNIEUW AANGEMAAKT,
// bij elke wijziging van de systeemtaal, enz. In de Activity opgebouwde services
// zouden dus bij elke rotatie opnieuw worden opgebouwd. Het
// Application-object daarentegen wordt aangemaakt wanneer het proces start
// en leeft zolang dit proces: het is de juiste plaats voor objecten die
// de hele levensduur van de applicatie moeten meegaan. Het wordt gedeclareerd in
// AndroidManifest.xml (attribuut android:name van de tag <application>).
//
// De VOLGORDE van opbouw is van belang, net als in de Flutter-versie:
// AuthService heeft SettingsService nodig (de server-URL); de geauthenticeerde
// HTTP-client heeft AuthService nodig (het token); AppointmentService heeft
// de geauthenticeerde HTTP-client en SettingsService nodig.
// =========================================================================

package fr.rdvmedecins.client

import android.app.Application
import android.content.Context
import fr.rdvmedecins.client.core.http.AuthInterceptor
import fr.rdvmedecins.client.core.i18n.TranslationsService
import fr.rdvmedecins.client.core.services.AuthService
import fr.rdvmedecins.client.core.services.AppointmentService
import fr.rdvmedecins.client.core.services.SettingsService
import okhttp3.OkHttpClient
import java.util.concurrent.TimeUnit

class RdvMedecinsApplication : Application() {

    // lateinit: deze niet-null-eigenschappen worden geïnitialiseerd in
    // onCreate() en niet in de constructor (zie de Kotlin-cursus)
    lateinit var settings: SettingsService
        private set
    lateinit var auth: AuthService
        private set
    lateinit var api: AppointmentService
        private set
    lateinit var translations: TranslationsService
        private set

    // door Android aangeroepen wanneer de applicatie start, vóór elk scherm
    override fun onCreate() {
        super.onCreate()

        // de voorkeuren van de applicatie: een klein privébestand met
        // sleutel/waarde-paren dat het stoppen van de applicatie overleeft - het
        // equivalent van de localStorage van een browser
        val prefs = getSharedPreferences("rdvmedecins", Context.MODE_PRIVATE)

        // 1. eerst SettingsService: de andere hebben het nodig
        settings = SettingsService(prefs)

        // 2. een "gewone" OkHttp-HTTP-client, door AuthService gebruikt voor
        //    POST /login. Korte time-outs: op mobiel is een snelle foutmelding
        //    beter dan eindeloos wachten als de server
        //    onbereikbaar is (verkeerde URL, wifi uit...).
        val plainHttp = OkHttpClient.Builder()
            .connectTimeout(10, TimeUnit.SECONDS)
            .readTimeout(15, TimeUnit.SECONDS)
            .build()
        auth = AuthService(settings, prefs, plainHttp)

        // 3. de geauthenticeerde HTTP-client: een KOPIE van de vorige
        //    (newBuilder() hergebruikt de configuratie en de verbindingen),
        //    plus de interceptor die het JWT-token toevoegt
        val authHttp = plainHttp.newBuilder()
            .addInterceptor(AuthInterceptor(auth))
            .build()
        api = AppointmentService(authHttp, settings)

        // 4. de vertalingen: geen afhankelijkheid van de andere services
        translations = TranslationsService(assets, prefs)
    }
}

    • regel 34: de klasse breidt [android.app.Application] uit. Android maakt daarvan één enkele instantie aan wanneer het proces van de app start - vóór enige activity - en houdt die in stand tot het proces eindigt;
    • regels 38-44: de vier services, gedeclareerd als [lateinit var ... private set]: niet-null, later geïnitialiseerd (in [onCreate]) en alleen door deze klasse te wijzigen;
    • regel 54: [getSharedPreferences(...)] - de voorkeuren van de applicatie, een klein privébestand met sleutel/waarde-paren dat het afsluiten van de applicatie overleeft: het equivalent van [localStorage] in een browser en van het pakket [shared_preferences] van Flutter;
    • regels 63-66: een „eenvoudige” [OkHttp]-client, met korte time-outs. Een OkHttp-client is bedoeld om te worden GEDEELD: hij beheert een eigen pool van herbruikbare verbindingen;
    • regel 67: [AuthService] ontvangt de eenvoudige client: de route [/login] is de enige openbare route van de server; daarvoor is geen token nodig;

// -------------------------------------------------------------------------
// De TOESTAND en de LOGICA van het hoofdscherm: het deel "_AppRootState"
// van de lib/app.dart van de Flutter-versie (artsen, patiënten, weergegeven

// acties van de gebruiker (een agenda opzoeken, reserveren, annuleren).

// AppRoot (zie App.kt)? Omdat de Activity bij elke schermrotatie wordt vernietigd en
// opnieuw aangemaakt (zie RdvMedecinsApplication): een
// lokale toestand zou verloren gaan - de weergegeven agenda zou bij de minste
// kanteling van de telefoon verdwijnen. Een ViewModel (bibliotheek "lifecycle" van Android Jetpack)
// OVERLEEFT deze hercreaties: Android bewaart het en
// geeft het door aan de nieuwe Activity. Het wordt pas vernietigd wanneer het scherm
// definitief wordt verlaten. Flutter kent dit probleem niet: een rotatie
// vernietigt daar niets, alleen de schermgrootte verandert.

// De resulterende verdeling is klassiek op Android: App.kt TOONT, dit
// ViewModel BESLIST en roept de services aan.

package fr.rdvmedecins.client

import android.util.Log
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.setValue
import androidx.compose.runtime.snapshotFlow
import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewModelScope
import fr.rdvmedecins.client.core.models.DoctorDaySchedule
import fr.rdvmedecins.client.core.models.Client
import fr.rdvmedecins.client.core.models.SlotJson
import fr.rdvmedecins.client.core.models.Doctor
import fr.rdvmedecins.client.core.models.AppointmentJson
import fr.rdvmedecins.client.core.services.AuthService
import fr.rdvmedecins.client.core.services.AppointmentService
import kotlinx.coroutines.CancellationException
import kotlinx.coroutines.launch

class AppViewModel(
    private val auth: AuthService,
    private val api: AppointmentService,
) : ViewModel() {

    // toestand die door App.kt wordt weergegeven (publiek lezen, privé schrijven)
    var doctors by mutableStateOf<List<Doctor>>(emptyList())
        private set
    var clients by mutableStateOf<List<Client>>(emptyList())
        private set
    var schedule by mutableStateOf<DoctorDaySchedule?>(null)
        private set
    var error by mutableStateOf<String?>(null)
        private set

    // het tijdslot dat wordt gereserveerd: niet null = het reserveringsdialoogvenster
    // is geopend (zie App.kt en BookingDialog.kt)
    var slotBeingBooked by mutableStateOf<SlotJson?>(null)
        private set

    // de laatste zoekopdracht (arts + dag), om de agenda te vernieuwen na
    // een reservering of annulering. Nooit weergegeven: gewone
    // eigenschappen volstaan, het hoeven geen Compose-toestanden te zijn.
    private var lastDoctorId: Int? = null
    private var lastDay: String? = null

    init {
        // snapshotFlow { ... } zet het lezen van een Compose-toestand om in een
        // FLOW van waarden: het zendt de huidige waarde van auth.isLoggedIn
        // meteen uit, daarna elke nieuwe waarde. Het is het exacte equivalent
        // van het "watch(() => auth.isLoggedIn, ..., { immediate: true })" van Vue.js
        // - en van het abonnement met addListener(...) + de initiële aanroep
        // die de Flutter-versie met de hand moest schrijven.
        // viewModelScope: de coroutines die in deze scope worden gestart, worden
        // automatisch geannuleerd wanneer het ViewModel wordt vernietigd (het
        // removeListener(...) van dispose() aan de Flutter-kant is niet meer nodig).
        viewModelScope.launch {
            snapshotFlow { auth.isLoggedIn }.collect { loggedIn ->
                if (loggedIn) {
                    loadInitialLists()
                } else {
                    reset()
                }
            }
        }
    }

    // -----------------------------------------------------------------------
    // bij het inloggen (of wanneer een onthouden sessie wordt hersteld): we
    // laden de artsen en de patiënten één keer. Twee
    // afzonderlijke coroutines: de twee verzoeken worden PARALLEL verstuurd.
    // -----------------------------------------------------------------------
    private fun loadInitialLists() {
        runSafely { doctors = api.getAllDoctors() }
        runSafely { clients = api.getAllClients() }
    }

    // -----------------------------------------------------------------------
    // bij het uitloggen (knop, of token geweigerd door de server): we
    // wissen de bedrijfstoestand, zodat een nieuwe gebruiker niet, ook niet heel
    // even, de agenda van de vorige gebruiker ziet
    // -----------------------------------------------------------------------
    private fun reset() {
        doctors = emptyList()
        clients = emptyList()
        schedule = null
        error = null
        slotBeingBooked = null
        lastDoctorId = null
        lastDay = null
    }

    // knop "Log out": het volstaat AuthService uit te loggen -
    // snapshotFlow (zie init) activeert dan reset()
    fun logOut() {
        auth.logOut()
    }

    // -----------------------------------------------------------------------
    // knop "View schedule" van DoctorDayPicker
    // -----------------------------------------------------------------------
    fun searchSchedule(doctorId: Int, day: String) {
        error = null
        lastDoctorId = doctorId
        lastDay = day
        loadSchedule()
    }

    // -----------------------------------------------------------------------
    // knop "Book" van ScheduleView: we OPENEN alleen het
    // dialoogvenster en onthouden het betreffende tijdslot. In Compose is een dialoogvenster
    // gewoon onderdeel van de weergave: het wordt
    // weergegeven zolang slotBeingBooked niet null is (zie App.kt) -
    // hetzelfde principe als de prop "open" van de BookingDialog.vue van de
    // Vue.js-variant, het tegenovergestelde van showDialog(...) in Flutter.
    // -----------------------------------------------------------------------
    fun requestBooking(slot: SlotJson) {
        slotBeingBooked = slot
    }

    // knop "Cancel" (of tikken buiten het venster) van het dialoogvenster
    fun closeBooking() {
        slotBeingBooked = null
    }

    // knop "Confirm" van het dialoogvenster
    fun confirmBooking(clientId: Int) {
        val slot = slotBeingBooked ?: return
        val day = lastDay ?: return
        slotBeingBooked = null // sluit het dialoogvenster
        runSafely {
            api.addAppointment(day, clientId, slot.id)
            loadSchedule() // het tijdslot verschijnt nu als bezet
        }
    }

    // -----------------------------------------------------------------------
    // knop "Cancel" van een bezet tijdslot, in ScheduleView
    // -----------------------------------------------------------------------
    fun cancelAppointment(appointment: AppointmentJson) {
        runSafely {
            api.deleteAppointment(appointment.id)
            loadSchedule() // het tijdslot komt weer vrij
        }
    }

    private fun loadSchedule() {
        val doctorId = lastDoctorId ?: return
        val day = lastDay ?: return
        runSafely { schedule = api.getDoctorScheduleOfDay(doctorId, day) }
    }

    // -----------------------------------------------------------------------
    // voert [action] uit in een coroutine van het ViewModel en zet elke
    // exception om in een foutmelding die op het scherm wordt getoond. Door deze
    // try/catch af te splitsen hoeft die niet in elke methode hierboven te worden herhaald.
    // Een CancellationException is GEEN fout: het is het annuleringssignaal
    // van een coroutine (ViewModel vernietigd), en dat moet
    // worden doorgegeven.
    // -----------------------------------------------------------------------
    private fun runSafely(action: suspend () -> Unit) {
        viewModelScope.launch {
            try {
                action()
            } catch (e: CancellationException) {
                throw e
            } catch (e: Exception) {
                Log.w("RdvMedecins", "a server call failed", e) // zie Logcat
                error = e.message ?: e.toString()
            }
        }
    }
}

// ServerResponse<T>. Hier gaan we in TWEE stappen te werk, om een specifieke reden: bij
// een fout zet de server een lijst met berichten in "data"
// (List<String>), waar we bij succes bijvoorbeeld een agenda verwachten.
// Het meteen decoderen van {status, data} als ServerResponse<DoctorDaySchedule> zou
// dus mislukken bij een foutantwoord, nog vóór de status is gelezen.
//   1. we lezen de envelop als generieke JSON-boom (JsonObject);
//   2. we controleren status; alleen als die 0 is, decoderen we "data" naar het
//      verwachte type.

package fr.rdvmedecins.client.core.models

import kotlinx.serialization.DeserializationStrategy
import kotlinx.serialization.json.Json
import kotlinx.serialization.json.JsonNull
import kotlinx.serialization.json.int
import kotlinx.serialization.json.jsonObject
import kotlinx.serialization.json.jsonPrimitive

// de JSON-configuratie die door de hele client wordt gedeeld:
// - ignoreUnknownKeys: de server stuurt velden die deze client
//   niet gebruikt (bijv. de "version" van een arts) - we negeren ze in plaats van
//   een exception te werpen;
// - explicitNulls = false: bij het coderen wordt een null-eigenschap niet
//   geschreven (geen effect op de klassen van deze client, maar dichter bij het
//   gedrag van JSON.stringify aan de JavaScript-kant).
val ApiJson = Json {
    ignoreUnknownKeys = true
    explicitNulls = false
}

// exception die wordt geworpen wanneer de server antwoordt met een andere bedrijfsstatus
// dan 0 (resource niet gevonden, ongeldige datum, serverfout)
class ResponseException(val status: Int) :
    Exception("The server responded with error status $status")

// decodeert de body van een antwoord {status, data} en geeft "data" terug in het
// type T dat door [deserializer] wordt beschreven (bijv. Doctor.serializer() of
// ListSerializer(Doctor.serializer()) voor een lijst met artsen)
fun <T> decodeResponse(body: String, deserializer: DeserializationStrategy<T>): T {
    // 1. de envelop, als generieke JSON-boom
    val envelope = ApiJson.parseToJsonElement(body).jsonObject
    // 2. de bedrijfsstatus
    val status = envelope.getValue("status").jsonPrimitive.int
    if (status != 0) {
        throw ResponseException(status)
    }
    // 3. "data", pas nu gedecodeerd naar het verwachte type
    val data = envelope["data"] ?: JsonNull
    return ApiJson.decodeFromJsonElement(deserializer, data)
}

package fr.rdvmedecins.client.core.services

import android.content.SharedPreferences
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.setValue

import okhttp3.Request
import okhttp3.RequestBody.Companion.toRequestBody
import java.io.IOException

class AuthService(
    private val settings: SettingsService,
    private val prefs: SharedPreferences,
    // een HTTP-client ZONDER de authenticatie-interceptor: POST /login
    // is de enige openbare route van de server, er is geen token
    // om te versturen (zie RdvMedecinsApplication)
    private val http: OkHttpClient,
) {
    // toestand van de sessie, door de UI geobserveerd
    var isLoggedIn by mutableStateOf(false)
        private set
    var login by mutableStateOf<String?>(null)
        private set
    var name by mutableStateOf<String?>(null)
        private set
    var role by mutableStateOf<Role?>(null)
        private set

    // het token wordt nooit WEERGEGEVEN: het hoeft geen Compose-toestand te zijn.
    // Het wordt wel gelezen door AuthInterceptor op een netwerkthread:
    // @Volatile garandeert dat deze thread altijd de laatste waarde ziet
    // die door de hoofdthread is geschreven.
    @Volatile
    var accessToken: String? = null
        private set

    // berekende eigenschap: leest role bij elke toegang opnieuw (en, wanneer ze tijdens een
    // weergave wordt gelezen, abonneert ze de weergave op de wijzigingen van role)
    val isAdmin: Boolean
        get() = role == Role.ADMIN

    init {
        restoreSession()
    }

    // -----------------------------------------------------------------------
    // een eventueel tijdens een eerdere start opgeslagen sessie opnieuw lezen
    // -----------------------------------------------------------------------
    private fun restoreSession() {
        val raw = prefs.getString(SESSION_KEY, null) ?: return // geen opgeslagen sessie
        try {
            // de sessie is opgeslagen als een LoginResult
            // geserialiseerd als JSON (zie logIn): we lezen die ongewijzigd terug
            applySession(ApiJson.decodeFromString(LoginResult.serializer(), raw))
        } catch (e: Exception) {
            // onleesbare inhoud (bijv. het formaat van een oude versie van
            // de applicatie): we vergeten die, de gebruiker logt opnieuw in
            prefs.edit { remove(SESSION_KEY) }
        }
    }

    // -----------------------------------------------------------------------
    // POST /login. "suspend": deze functie kan pauzeren gedurende de
    // tijd die de server nodig heeft om te antwoorden, ZONDER de aanroepende thread te blokkeren -
    // het equivalent van een async-functie die een Future<LoginResult> teruggeeft
    // aan de Dart-kant. Ze werpt een exception als het inloggen mislukt.
    // -----------------------------------------------------------------------
    suspend fun logIn(login: String, password: String): LoginResult {
        // withContext(Dispatchers.IO): het blok draait op een thread
        // die is gereserveerd voor invoer/uitvoer. Android VERBIEDT elke netwerktoegang
        // vanuit de hoofdthread (NetworkOnMainThreadException): die
        // tekent de UI en mag nooit wachten.
        val result = withContext(Dispatchers.IO) {
            val body = ApiJson.encodeToString(LoginRequest.serializer(), LoginRequest(login, password))
            val request = Request.Builder()
                .url("${settings.apiBaseUrl}/login")
                .post(body.toRequestBody(JSON_TYPE))
                .build()
            // execute(): een BLOKKERENDE aanroep - hier onschadelijk, we zitten op een
            // invoer-/uitvoerthread. use { } sluit het antwoord aan het einde van het
            // blok, wat er ook gebeurt (het equivalent van Java's
            // try-with-resources, zie de Kotlin-cursus).
            http.newCall(request).execute().use { response ->
                // onjuiste inloggegevens: de server antwoordt 401 Unauthorized
                if (!response.isSuccessful) {
                    throw IOException("Login failed (HTTP ${response.code})")
                }
                decodeResponse(response.body!!.string(), LoginResult.serializer())
            }
        }
        // terug op de thread van de aanroeper (de hoofdthread):
        // hier, en niet op de invoer-/uitvoerthread, wijzigen we
        // de toestand die door de UI wordt geobserveerd
        applySession(result)
        prefs.edit { putString(SESSION_KEY, ApiJson.encodeToString(LoginResult.serializer(), result)) }
        return result
    }

    // -----------------------------------------------------------------------
    // uitloggen: we vergeten de sessie, in het geheugen en in de voorkeuren.
    // Moet op de hoofdthread worden aangeroepen (zie AuthInterceptor).
    // -----------------------------------------------------------------------
    fun logOut() {
        accessToken = null
        login = null
        name = null
        role = null
        isLoggedIn = false
        prefs.edit { remove(SESSION_KEY) }
    }

    private fun applySession(session: LoginResult) {
        accessToken = session.accessToken
        login = session.login
        name = session.name
        role = session.role
        isLoggedIn = true
    }

    companion object {
        private const val SESSION_KEY = "rdvmedecins.session"
        private val JSON_TYPE = "application/json; charset=utf-8".toMediaType()
    }
}

class AppointmentService(
    private val http: OkHttpClient,
    private val settings: SettingsService,

    // de GET-routes
    // -----------------------------------------------------------------------
    suspend fun getAllDoctors(): List<Doctor> =
        call(getRequest("/getAllDoctors"), ListSerializer(Doctor.serializer()))

    suspend fun getAllClients(): List<Client> =
        call(getRequest("/getAllClients"), ListSerializer(Client.serializer()))

    suspend fun getDoctorScheduleOfDay(doctorId: Int, day: String): DoctorDaySchedule =
        call(getRequest("/getDoctorScheduleOfDay/$doctorId/$day"), DoctorDaySchedule.serializer())

    // -----------------------------------------------------------------------
    // de POST-routes (door de server voorbehouden aan de rol ADMIN)
    // -----------------------------------------------------------------------

        val body = ApiJson.encodeToString(
            AddAppointmentRequest.serializer(),
            AddAppointmentRequest(day, clientId, slotId),
        )
        return call(postRequest("/addAppointment", body), AppointmentJson.serializer())
    }

    suspend fun deleteAppointment(appointmentId: Int) {
        val body = ApiJson.encodeToString(DeleteAppointmentRequest.serializer(), DeleteAppointmentRequest(appointmentId))
        // bij succes is "data" null: we decoderen het als een
        // willekeurig JSON-element en negeren het
        call(postRequest("/deleteAppointment", body), JsonElement.serializer())
    }

    // de verzoeken opbouwen

            .post(jsonBody.toRequestBody(JSON_TYPE))
            .build()

    // antwoord {status, data}. De generieke parameter <T> en de
    // bijbehorende [deserializer] geven aan naar welk type
    // "data" moet worden gedecodeerd - de rol van de parameter parseData van de Flutter-versie.

                // 401 (token geweigerd), 403 (onvoldoende rol), 404...: de

                    throw IOException("HTTP error ${response.code}")
                }
                decodeResponse(response.body!!.string(), deserializer)
            }
        }

    companion object {
        private val JSON_TYPE = "application/json; charset=utf-8".toMediaType()
    }
}

class AuthInterceptor(private val auth: AuthService) : Interceptor {

    // werk aan overdragen vanuit een andere thread (zie intercept hieronder)

    // door OkHttp aangeroepen voor ELK verzoek, op een netwerkthread
    override fun intercept(chain: Interceptor.Chain): Response {
        // 1. het oorspronkelijke verzoek, plus het token als er een is. Een
        //    OkHttp-verzoek is onveranderlijk: newBuilder() maakt er een
        //    wijzigbare kopie van.
        val token = auth.accessToken
        val request = if (token == null) {
            chain.request()
        } else {
            chain.request().newBuilder()
                .header("Authorization", "Bearer $token")
                .build()
        }
        // 2. we laten het verzoek zijn weg naar de server vervolgen
        val response = chain.proceed(request)
        // 3. token geweigerd: we loggen de gebruiker uit. Deze methode
        //    draait op een netwerkthread; toch wijzigt logOut()
        //    de toestand die door de UI wordt weergegeven: daarom dragen we deze aanroep over aan de
        //    hoofdthread (post), zonder te wachten tot ze is uitgevoerd - de
        //    tegenhanger van de unawaited(auth.logOut()) van de Flutter-versie.
        if (response.code == 401) {
            mainThread.post { auth.logOut() }
        }
        return response
    }
}

    Laten we deze code toelichten:

    • Regel 26: de klasse implementeert de interface [okhttp3.Interceptor]. OkHttp stuurt elk verzoek door de interceptors van de client voordat het wordt verzonden, en elk antwoord voordat het naar de aanroeper teruggaat: dit is hetzelfde concept als de HTTP-interceptors van Angular. De Flutter-versie, die zo’n mechanisme niet had in het pakket [http], verpakte de HTTP-client in een eigen klasse;
    • regel 30: een [Handler] die aan de hoofdthread is gekoppeld ([Looper.getMainLooper()]): hiermee kan werk vanuit een andere thread aan de hoofdthread worden overgedragen;
    • regels 41–43: een OkHttp-verzoek is ONVERANDERLIJK; [newBuilder()] maakt er een aanpasbare kopie van, aangevuld met de header [Authorization];
    • regel 46: [chain.proceed(request)] – het verzoek gaat verder naar de server; de methode geeft het antwoord terug;
    • regels 52–53: token geweigerd (401): [intercept] draait op een netwerkthread, maar [logOut()] wijzigt de weergegeven toestand. De aanroep wordt daarom aan de hoofdthread overgedragen ([post { ... }]), zonder te wachten tot ze is uitgevoerd – het equivalent van [unawaited(auth.logOut())] in de Flutter-versie.

// Port van lib/core/i18n/translations_service.dart: de UI direct omschakelen tussen
// Frans en Engels, zonder de

// assets die in de pubspec.yaml van de Flutter-versie zijn gedeclareerd.

// applicatie te vertalen berust op de resourcebestanden res/values/strings.xml
// (Engels) en res/values-fr/strings.xml (Frans), waarbij het systeem
// het juiste bestand kiest op basis van de taal van de TELEFOON. Dit document
// behoudt de JSON-woordenboeken die door alle varianten van de cursus worden gedeeld,
// en de FR/EN-schakelaar binnen de applicatie zelf, zoals de
// oorspronkelijke applicatie (2014) deed.

package fr.rdvmedecins.client.core.i18n

import android.content.SharedPreferences
import android.content.res.AssetManager
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.setValue
import androidx.core.content.edit
import fr.rdvmedecins.client.core.models.ApiJson
import kotlinx.serialization.json.JsonElement
import kotlinx.serialization.json.JsonObject
import kotlinx.serialization.json.JsonPrimitive
import kotlinx.serialization.json.jsonObject

class TranslationsService(
    private val assets: AssetManager,
    private val prefs: SharedPreferences,
) {
    // de weergegeven taal: een Compose-toestand. Omdat t(...) hieronder deze
    // eigenschap LEEST, wordt elke met t(...) weergegeven tekst automatisch
    // opnieuw weergegeven wanneer de taal verandert - geen context.watch<...>() om
    // te schrijven, anders dan in de Flutter-versie.
    var currentLanguage by mutableStateOf(prefs.getString(LANGUAGE_KEY, null) ?: DEFAULT_LANGUAGE)
        private set

    // de reeds geladen woordenboeken, per taal ("fr" -> {...})
    private val dictionaries = mutableMapOf<String, JsonObject>()

    fun changeLanguage(language: String) {
        if (language == currentLanguage) {
            return
        }
        dictionary(language) // het woordenboek laden VOORDAT de taal wordt gewijzigd
        currentLanguage = language
        prefs.edit { putString(LANGUAGE_KEY, language) }
    }

    // -----------------------------------------------------------------------
    // t("LOGIN.TITLE"): doorloopt het woordenboek van de huidige taal
    // segment voor segment ("LOGIN", daarna "TITLE"). Als de sleutel
    // niet wordt gevonden, wordt de sleutel zelf geretourneerd: de ontbrekende tekst blijft zo
    // zichtbaar op het scherm, zonder de applicatie te laten crashen.
    // -----------------------------------------------------------------------
    fun t(key: String): String {
        var currentValue: JsonElement = dictionary(currentLanguage)
        for (segment in key.split('.')) {
            currentValue = (currentValue as? JsonObject)?.get(segment) ?: return key
        }
        val primitive = currentValue as? JsonPrimitive
        return if (primitive != null && primitive.isString) primitive.content else key
    }

    // -----------------------------------------------------------------------
    // het woordenboek van een taal, geladen wanneer het voor het eerst nodig is en daarna in het
    // geheugen bewaard. getOrPut: geeft de aan de sleutel gekoppelde waarde terug, of voert
    // het blok uit, slaat het resultaat op en geeft het terug. Het lezen is
    // synchroon: de twee bestanden zijn slechts enkele honderden
    // bytes groot, ze lezen gaat razendsnel.
    // -----------------------------------------------------------------------
    private fun dictionary(language: String): JsonObject =
        dictionaries.getOrPut(language) {
            assets.open("i18n/$language.json").bufferedReader().use { reader ->
                ApiJson.parseToJsonElement(reader.readText()).jsonObject
            }
        }

    companion object {
        private const val LANGUAGE_KEY = "rdvmedecins.language"
        private val DEFAULT_LANGUAGE = if (java.util.Locale.getDefault().language == "fr") "fr" else "en"
    }
}

    Laten we deze code toelichten:

    • Regels 43–44: [currentLanguage] – een waarneembare toestand. Omdat [t(...)] deze eigenschap LEEST, wordt elke @Composable-functie die tekst toont met [t(...)] automatisch opnieuw samengesteld wanneer de taal verandert: het is niet nodig om [context.watch<...>()] te schrijven;
    • regels 49–55: [changeLanguage(...)] – laadt het woordenboek VOORDAT van taal wordt gewisseld, en slaat daarna de keuze op in de voorkeuren;
    • Regels 64–70: [t("LOGIN.TITLE")] – doorloopt het woordenboek segment voor segment. [as?] is de „veilige” typeconversie van Kotlin: ze geeft [null] terug (in plaats van een exception te gooien) als het object niet van het gevraagde type is; in combinatie met [?: return key] zorgt dit ervoor dat de sleutel zelf wordt teruggegeven zodra een segment niet wordt gevonden – de ontbrekende tekst blijft zichtbaar op het scherm;
    • regels 80–83: [dictionary(language)] – [getOrPut] geeft het al geladen woordenboek terug, of voert het blok uit (waarbij [assets/i18n/<language>.json] wordt gelezen), slaat het resultaat op en geeft het terug. Het lezen gebeurt synchroon: beide bestanden zijn slechts enkele honderden bytes groot.

// de API's ExposedDropdownMenu* zijn door Material 3 nog als "experimental"
// gemarkeerd: @OptIn geeft aan dat we ze bewust gebruiken
@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun <T> DropdownList(
    label: String,
    placeholder: String,     // tekst die wordt weergegeven zolang er niets is gekozen
    items: List<T>,
    selectedId: Int?,        // id van het gekozen item, of null
    idOf: (T) -> Int,
    itemLabel: (T) -> String,
    onSelect: (Int) -> Unit,
    modifier: Modifier = Modifier,
) {
    // menu geopend of gesloten: een toestand die LOKAAL is voor deze functie en van de ene
    // weergave naar de volgende wordt onthouden door remember (zie hoofdstuk 3)
    var menuOpen by remember { mutableStateOf(false) }
    val selected = items.firstOrNull { idOf(it) == selectedId }

    ExposedDropdownMenuBox(
        expanded = menuOpen,
        onExpandedChange = { menuOpen = it },
        modifier = modifier,
    ) {
        // het veld dat de huidige keuze toont; menuAnchor(...) maakt er
        // het ankerpunt van het menu van (een klik erop opent het menu)
        OutlinedTextField(
            value = selected?.let(itemLabel) ?: "",
            onValueChange = {},
            readOnly = true,
            singleLine = true,
            label = { Text(label) },
            placeholder = { Text(placeholder) },
            trailingIcon = { ExposedDropdownMenuDefaults.TrailingIcon(expanded = menuOpen) },
            modifier = Modifier
                .menuAnchor(ExposedDropdownMenuAnchorType.PrimaryNotEditable)
                .fillMaxWidth(),
        )
        // het menu zelf: één DropdownMenuItem per item
        ExposedDropdownMenu(expanded = menuOpen, onDismissRequest = { menuOpen = false }) {
            items.forEach { item ->
                DropdownMenuItem(
                    text = { Text(itemLabel(item)) },
                    onClick = {
                        onSelect(idOf(item))
                        menuOpen = false
                    },
                )
            }
        }
    }
}

package fr.rdvmedecins.client.features.bookingdialog

import androidx.compose.foundation.layout.Arrangement
import androidx.compose.foundation.layout.Column

import androidx.compose.material3.Button

import androidx.compose.runtime.Composable

import androidx.compose.runtime.saveable.rememberSaveable

import fr.rdvmedecins.client.core.LocalTranslations
import fr.rdvmedecins.client.core.models.Client
import fr.rdvmedecins.client.core.models.SlotJson
import fr.rdvmedecins.client.core.ui.DropdownList

@Composable
fun BookingDialog(
    slot: SlotJson,
    clients: List<Client>,
    onConfirm: (clientId: Int) -> Unit,
    onClose: () -> Unit,
) {
    val t = LocalTranslations.current::t
    // de gekozen patiënt (zijn id), of null zolang er geen is gekozen
    var clientId by rememberSaveable { mutableStateOf<Int?>(null) }

    AlertDialog(
        // tikken buiten het dialoogvenster of de toets "back" van de telefoon
        onDismissRequest = onClose,
        title = { Text(t("BOOKING_DIALOG.TITLE")) },
        text = {
            Column(verticalArrangement = Arrangement.spacedBy(16.dp)) {
                Text(
                    "${t("BOOKING_DIALOG.SLOT_FROM")} ${slot.startHour}:${slot.startMinute.toString().padStart(2, '0')} " +
                        "${t("BOOKING_DIALOG.SLOT_TO")} ${slot.endHour}:${slot.endMinute.toString().padStart(2, '0')}",
                )
                DropdownList(
                    label = t("BOOKING_DIALOG.PATIENT_LABEL"),
                    placeholder = t("BOOKING_DIALOG.CHOOSE_PATIENT"),
                    items = clients,
                    selectedId = clientId,
                    idOf = { it.id },
                    itemLabel = { "${it.title} ${it.firstName} ${it.lastName}" },
                    onSelect = { clientId = it },
                    modifier = Modifier.fillMaxWidth(),
                )
            }
        },
        // "Confirm": uitgeschakeld zolang er geen patiënt is gekozen
        confirmButton = {
            Button(
                enabled = clientId != null,
                onClick = { clientId?.let(onConfirm) },
            ) { Text(t("BOOKING_DIALOG.CONFIRM")) }
        },
        dismissButton = {
            TextButton(onClick = onClose) { Text(t("BOOKING_DIALOG.CANCEL")) }
        },
    )
}

    • regels 8–15: De commentaarkop vat het structurele verschil met de Flutter-versie samen. Flutter OPENDE het dialoogvenster met [showDialog(...)] en WACHTTE op het resultaat (een [Future<int?>]). In Compose is een dialoogvenster een view-element zoals elk ander: het blijft getoond zolang de functie die het aanroept het blijft aanroepen. Het „retourneert” niets: het meldt de keuze via twee functies, [onConfirm] en [onClose] – precies de twee gebeurtenissen [confirm] / [close] van het component [BookingDialog.vue] in de Vue.js-variant;
    • regel 48: de gekozen patiënt: [rememberSaveable]; de patiënt blijft geselecteerd, ook als het scherm roteert terwijl het dialoogvenster open is;
    • regels 50–52: [AlertDialog(...)] – het dialoogvenster van Material 3, met een titel, inhoud ([text]) en twee knoppen. [onDismissRequest] wordt aangeroepen wanneer de gebruiker buiten het dialoogvenster tikt of op de knop „Terug” van de telefoon drukt;
    • regels 73–76: de knop „Confirm”, die is uitgeschakeld totdat een patiënt is geselecteerd. [clientId?.let(onConfirm)]: als [clientId] niet [null] is, wordt [onConfirm] aangeroepen met de waarde ervan.
